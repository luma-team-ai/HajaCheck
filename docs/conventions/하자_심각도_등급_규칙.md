## 1. 목적·범위

- 탐지된 하자 각각에 대해 **심각도를 A~E 5등급으로 산정**하는 규칙을 정의한다.
- 대상 클래스 3종(확정): **균열 · 박리·박락 · 철근 노출**.
- **규칙기반 1차**(크기·유형 기준). 산정 결과는 점검자가 검수 단계에서 **수동 조정 가능**(PRD FR-4, `defect_revisions` append-only 기록).
- 시설물 안전등급(A~E) 관행을 준용 — **A=우수(경미), E=불량(심각)**.

---

## 2. 등급 정의 (A=우수 ~ E=불량)

**등급 점수 `g ∈ [0, 1]`** — 높을수록 양호. 하자가 심할수록 낮은 점수를 받아 낮은 등급(E)으로 간다.
`g = 1 − s` (s = 심각도 원점수, §3). **0.2 단위** 버킷.

| 등급 | 점수 `g` 범위 | 의미 | 안전등급 준용 |
|---|---|---|---|
| **A** | 0.8 ≤ g ≤ 1.0 | 경미 | 우수 |
| **B** | 0.6 ≤ g < 0.8 | 양호 | 양호 |
| **C** | 0.4 ≤ g < 0.6 | 보통 | 보통 |
| **D** | 0.2 ≤ g < 0.4 | 주의 | 미흡 |
| **E** | 0.0 ≤ g < 0.2 | 심각 | 불량 |

**경계 처리(off-by-one 방지)**: `g ≥ 0.8 → A`, `0.6 ≤ g < 0.8 → B`, `0.4 ≤ g < 0.6 → C`, `0.2 ≤ g < 0.4 → D`, `g < 0.2 → E` (상단 닫힘 A만 1.0 포함, 나머지 `[lo, hi)` 반열림).

---

## 3. 규칙 1 — 심각도 원점수 `s` 와 임계값 (크기 · 유형)

심각도 원점수 **`s ∈ [0, 1]`** (높을수록 심각) 을 **크기 프록시 × 유형 가중**으로 산출한다.

### 3.1 크기 프록시 (1차)
- 정량 실측(균열 폭·길이 mm)은 PRD **P1**(픽셀→실측 환산). **1차 규칙기반에서는 YOLOv8-seg 산출물의 마스크 면적 비율을 프록시**로 사용한다.
- `area_ratio = (하자 마스크 픽셀 면적) / (이미지 전체 픽셀 면적)` — 0~1.

### 3.2 유형별 산정 (초안 — 튜닝 대상)

| 유형 | 크기 프록시 | s 산정(1차 초안) | 비고 |
|---|---|---|---|
| 균열(crack) | 마스크 길이/면적 비율 | area_ratio 구간 매핑(아래) | P1에서 폭·길이 정량으로 대체 |
| 박리·박락(spalling) | 마스크 면적 비율 | area_ratio 구간 매핑 | 면적형 |
| 철근 노출(rebar) | 존재 + 면적 비율 | **기본 하한 s₀=0.6** + area 가중 | 존재 자체가 고위험 → 최소 D 이하로 시작 |

**area_ratio → s 구간(공통 초안, %기준)**:

| area_ratio | s | (철근노출 보정 후) |
|---|---|---|
| < 1% | 0.1 | max(0.1, 0.6) = 0.6 |
| 1 ~ 3% | 0.3 | 0.6 |
| 3 ~ 7% | 0.5 | 0.6 |
| 7 ~ 15% | 0.7 | 0.7 |
| ≥ 15% | 0.9 | 0.9 |

> ⚠️ 위 표는 **v0.1 시점의 1차 가정치**이며, **박리·박락 / 철근 노출에만 현행으로 유효**하다(`grading.py:_DEFAULT_AREA_RATIO_SEVERITY_BANDS`와 일치). **균열은 아래 §3.3의 전용 규칙으로 대체**됐다. 한 이미지에 하자 다수 시 등급은 **하자별로 개별 산정**(집계 등급이 필요하면 최저 등급 = 최악 하자 기준).

### 3.3 균열(CRACK) 전용 규칙 — 2지표 min 합의 + v4 밴드 (2026-08-04 현행)

균열은 선형 하자라 공통 area_ratio 표를 쓸 수 없다. 두 번의 정정을 거쳐 **면적비 + 어두움총량 2지표**를 쓴다.

| 세대 | 시점 | 무엇이 바뀌었나 | 결과 |
|---|---|---|---|
| v1 | 2026-07-26 | YOLO + "이미지당 최대 인스턴스 1개" 기준 | 폐기 |
| v2 | 2026-07-27 | U-Net 교체 + 집계를 **콘텐츠 영역 전체 마스크 합**으로 변경 → 470장 재측정 | 과대경고 해소(심각알람 정밀도 64.7% 회복) |
| v3 | 2026-07-28 | **면적비 단독 → 면적비 + 어두움총량(dark_ratio) 2지표 중 낮은 등급 채택**(min 합의) | 심각알람 F1 81.3% → **84.2%** |
| **v4** | **2026-08-03** | 균열 모델을 **`crack_unet_resnet34_v2`(현장사진 70장 파인튜닝)** 로 교체 → area·dark 양쪽 밴드 재교정 | 심각알람 F1 **87.9%** · 3등급 정확도 70.2% → **79.6%** |

**왜 2지표인가** — area는 길이 × 폭인데 U-Net 마스크 폭은 실제 굵기와 무관하게 3~4px가 하한(640 입력에서 0.3mm ≈ 0.2px)이라 **사실상 길이만 재는 값**이다. 그래서 "가늘지만 긴" 실금이 D·E로 과대판정됐다. 서브픽셀 영역에서 진짜 폭에 비례하는 광학 신호인 **BLACKHAT 어두움총량**을 두 번째 지표로 두고, **두 등급 중 낮은 쪽을 채택**한다 — 심각 판정에 "넓게 퍼졌다"와 "짙다"를 **둘 다** 요구하는 것이다.

**현행 밴드(v4)** — 상한 미만, 마지막 구간만 이상. 값의 정본은 `grading.py`다.

| s | area_ratio 미만 | dark_ratio 미만 |
|---|---|---|
| 0.1 | 0.00002956 | 0.00000897 |
| 0.3 | 0.00070104 | 0.00010537 |
| 0.5 | 0.00197858 | 0.00151626 |
| 0.7 | 0.00398633 | 0.00194422 |
| 0.9 | (이상) | (이상) |

### 3.4 재측정 트리거 규칙 (필수)

> **임계값은 "모델 · 전처리 · 집계 단위" 3조건에 종속된다 — 셋 중 하나라도 바뀌면 재측정한다.**
> v1 사고의 근본 원인은 "임계값 옆에 측정 조건이 적혀 있지 않았던 것"이다. 그래서 임계값과 측정 조건은 **항상 같은 자리에 기록**한다. v4가 이 규칙이 실제로 발동한 사례다(모델 교체 → 즉시 재교정). `dark_ratio` 산출 조건(BLACKHAT ellipse 15×15, 마스크 3×3 팽창 밴드, 255×콘텐츠픽셀 정규화)이 바뀌어도 dark 구간표 재측정 대상이다.

**미해결 — 프레이밍(촬영거리) 의존성**: area_ratio는 "촬영 조건이 유사하다"는 전제 하의 추정치다(같은 균열도 2배 가까이서 찍으면 값이 1.5~1.8배). **"촬영거리로 보정" 안은 2026-07-27 실측으로 철회**됐다 — 폭·거리 상관이 너무 약해(ρ≈−0.26) 과보정이 되고(AUC 0.87→0.78), 촬영거리 자체가 심각도와 교란된다. 밴드를 넓히는 대응도 원래 버그로 회귀하므로 하지 않는다.

## 4. 규칙 2 — 산정 위치 · 구현 (109 범위 밖, 후속 dev)

- **산정 위치 = FastAPI 탐지 후처리**(구현 완료). 추론 결과(class, mask, area) → `s` → `g` → grade 계산 → **추론 결과 payload에 `grade` 포함**해 반환. 균열은 U-Net 마스크를 연결요소 분석으로 인스턴스화한 뒤 `compute_crack_severity_score(area_ratio, dark_ratio)`로, 나머지 2종은 `compute_severity_score(defect_type, area_ratio)`로 산정한다.
  - 근거: `ai-server/ai/chains/defect_explain_chain.py` 가 이미 `severity_grade: str` 를 **입력으로 기대** → 등급은 상위(탐지 파이프라인)에서 계산해 넘기는 구조가 이미 전제됨.
- **임계값 저장**: 현재 ai-server **상수 모듈 하드코딩**(`ai/core/grading.py`). DB화는 후속 — 옛 "하자 유형·등급 기준 관리" 화면이 메뉴에서 삭제됐으므로 **DB화 시점 자체가 재검토 대상**이다(PRD §11).
- **저장 스키마**: `defects.grade` (A~E enum) 컬럼 — 하자 엔티티(하자 관리, 유병현) 생성 시 반영. `defects`에 원점수(`severity_score`)도 함께 저장하면 재계산·감사에 유리.
- **수동 조정**: 점검자 검수 시 등급 변경 → `defect_revisions` append-only 기록(FR-4 감사 추적).

## 5. 후속 개발 태스크 (본 문서=설계, 아래는 구현)

1. ai-server 등급 산정 함수 + 상수 임계값 (`grading.py`) — 탐지 파이프라인에 결합
2. `defects.grade`(A~E enum) + `severity_score` 컬럼 — 하자 엔티티/마이그레이션
3. 관리자 하자 유형·등급 기준 관리(dev-11-03) — 임계값 DB화·설정형
